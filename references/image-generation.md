# 出图调用与故障恢复

在调用图片工具前阅读本文件。技能负责地图内容与调用决策，图片工具及其客户端负责网络、鉴权和生成服务；修改技能不能修复客户端或服务端的网络链路。

## 调用约定

- 使用Codex内置 `image_gen.imagegen`，以本次工具的实际名称、说明和参数为准。工具未暴露的 `size`、`model`、超时或重试参数不自行添加；尺寸写入提示词只是期望，成功后仍须读取实际尺寸。
- 当前会话没有第二个独立的Codex内置出图工具时，不虚构备用；不同执行包装或同一工具重发不算另一种引擎。ChatGPT网页“创建图像”、浏览器复制图片及网页截图都不能作为本技能的Codex出图路径。
- 新图只提交最终提示词及工具需要的选项，不传历史图数量或本地参考路径。只有真实的编辑或参考图任务才使用这些字段，并遵守工具的图像读取要求。
- 提示词包含地点、编号、画风配色、地理关系、动线、图例与画幅。合并重复修饰，但不删除用户要求、删改编号或擅自降低尺寸。来源链接、技能说明与调试信息放在画面外。
- 从已交付提示词继续出图时，复用已确认的设计；不要把此前的“仅提示词”继续当成禁止出图的指令。
- 工具支持直接调用时直接调用；经执行单元调用时，等待图片工具完成，并使用其原生图片交付方式。执行单元返回运行编号只表示仍在执行，继续等待同一编号，不能另开一份生成请求。轮询等待不算出图重试；遵循当前工具规定的等待时长，不虚构完成百分比。

## 失败时先保全结果

1. 检查本次工具返回的状态、错误文本、请求编号和输出文件（如有）。只使用本次调用实际暴露的信息；未返回的HTTP状态、请求编号、底层网络原因写“未提供”，不猜测。
2. 若工具明确给出了输出路径或结果查询方式，先核对原结果，再考虑重发。不要通过新建生成请求来查询进度，也不扫描其他会话或不相关用户文件。
3. 有文件工具时，将实际发送的完整提示词保存到本次任务输出目录，如 `output/city-explorer-map/深圳/prompt.txt`；可同时保存简短 `generation-error.txt`，记录工具名、尝试次数、已知错误和结果是否未知。文件已存在则另存新版本。无文件工具时，直接在回复中提供完整提示词。
4. 交付可点击的提示词文件及一句错误摘要；不要只说“提示词已保留”而不给正文或文件。诊断内容不得包含密钥、令牌、私有请求头或其他会话信息。失败产物只是恢复材料，不表示图片任务已经完成。

## Codex备用选择

用户允许“错误时使用Codex自带生图工具”后，无需就同一次切换重复确认，但先核对失败的工具身份：

| 失败入口与当前可用能力 | 处理 |
| --- | --- |
| 失败的是用户另行选择的其他真实出图入口，当前有Codex内置 `image_gen.imagegen` | 先保全结果，告知切换，然后用完整提示词调用Codex内置工具一次；不要同时重试原入口 |
| 失败的已经是Codex内置 `image_gen.imagegen`，当前只有这一个生图工具 | 明确说明“刚才报错的就是Codex内置工具，目前没有另一个独立备用入口”；不能声称已完成备用切换 |
| 失败的是同一Codex工具的执行包装或别名 | 仍按同一工具处理，更换包装、技能名称或执行单元不算切换 |
| 当前未提供Codex内置生图工具 | 说明能力不可用并交付完整提示词，不能虚构调用成功或改开ChatGPT网页 |

备用授权不是无限重试授权。同一Codex工具长时间等待后报网络错误且结果未知时，遵守下节停止条件；用户明确要求重试才重新提交。原入口和Codex备用均失败时保留各自错误，停止循环切换。此规则不新增其他主引擎，也不改变本技能默认直接使用Codex内置工具的行为。

## 分类与有限重试

| 实际证据 | 处理 |
| --- | --- |
| 工具不存在、参数或参考图字段被明确拒绝 | 按当前工具契约修正明确的问题后再调用；不归因于网络 |
| `network error: error sending request`，无HTTP状态或细节 | 记为传输层错误，底层原因未知；不能推断为画风不支持、中文过多、提示词过长或额度不足 |
| 长时间等待后网络错误或超时，且没有可查询结果 | 结果未知，停止自动重发，交付完整提示词；待用户明确要求重试或有恢复证据后再尝试 |
| 明确的暂时性服务错误、限流，或请求尚未发送即失败 | 若能确认上次未产出图片或服务明确建议重试，按工具提供的等待建议最多自动重试一次；保留相同设计，再失败即停止。不能确认时按结果未知处理 |
| 明确的登录、鉴权、权限或额度错误 | 不自动重试，说明具体错误与用户需处理的事项；不读取凭据、不切换账号 |
| 明确的内容或输入错误 | 针对已指出的问题处理，保留用户意图，不把它伪装成网络错误，不原样循环提交 |
| 成图已返回但编号、文字、位置等有误 | 属于质量修正，按技能约定最多进行一次聚焦修改，不套用网络重试流程 |

用户明确要求重试时，可重新调用同一Codex内置工具一次，但须说明是重试，不称为备用。用户指定Codex时不再沿用旧的ChatGPT网页备用授权；内置工具不可用或失败就按上述停止条件交付恢复材料。

未知网络错误不会因为缩短提示词、删除作者名称、减少地标或更换画幅而被证明修复。不得把一次成功重试解释为已定位根因。采用其他服务、CLI或单独计费API，须有用户对该路径的明确选择；普通“修复技能”不表示授权切换服务或修改系统代理。

## 已观察到的故障与验证边界

2026-10-25，一次深圳地图生成及随后的一次重试均返回：

```text
image generation failed: network error: error sending request
```

当时工具未返回图片、HTTP状态或请求编号。可以确认调用以网络错误结束，无法进一步区分连接、代理、TLS、超时或服务端问题；也没有证据说明与Hergé画风、配色、地标数量或提示词长度有关。

故障恢复规则补足分类、结果保全和停止条件，不声称恢复了图片服务。1.0.3移除1.0.2的ChatGPT网页备用流程，固定使用Codex内置工具。仅修改技能时不自动生成测试图；用户同时要求使用Codex生成时，可复用当前地图方案实际调用，并单独记录该工具结果与图片检查结论。旧版网页成图不能证明Codex内置工具已成功生成。

OpenAI官方文档将连接错误与鉴权、限流等错误分开处理，并建议根据错误类型决定是否重试。这些API文档用于分类参考，不表示客户端内置工具暴露相同的HTTP字段或重试控制：
